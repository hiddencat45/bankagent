# 本地账本持久化

桌面入口默认使用 `%LOCALAPPDATA%/BankAgent/bankagent.sqlite3`。可通过 `BANKAGENT_DB_PATH` 指定另一文件；父目录不存在时创建。启动失败或数据库损坏会明确失败，不自动删除、重建或回退到内存。仓库忽略 SQLite 文件和日志；不要将真实个人数据或密钥放入演示账本。

## 保存边界

保存演示账户、联系人、卡片、订阅状态、交易流水及已完成操作的幂等回执。余额和对应流水、回执一并提交。初始样例仅在新数据库第一次创建时导入，重启读取已有数据；演示业务时间以首次建库时间为锚点继续推进，不因重启回退。

开户与双边转账已在后续增量接入；当前新转账会同时保存双方余额和关联流水。旧版单边转账保留原记录，不自动补入账。升级和消费控制见 [双边转账与消费限额](双边转账与消费限额.md)。理财推荐仍未接入。

聊天、登录会话、授权挑战和未完成操作不落库。重启后建立新会话、重新确认未执行操作。已完成回执保存在业务后端，可由可信服务端使用同一请求身份/幂等键查回；当前公开 API 与桌面界面尚不提供跨重启恢复旧确认或按回执检索功能，不宣称已经完成响应丢失后的完整用户恢复流程。

## 事务与格式

使用 Python 标准库 sqlite3，无新增第三方依赖。当前格式版本2沿用单行事务快照：`bank_state` 保存版本、业务数据 JSON、已完成回执 JSON 和建库时间，版本1会在事务内升级。金额仍是整数分，回执只包含操作指纹和执行结果，不保存 API 密钥、OTP 或授权口令。当前小规模演示采用完整快照，尚未拆成可直接 SQL 查询的客户/账户/交易关系表；升级不覆盖已有余额和历史流水。

每次业务调用在共享锁内开启 `BEGIN IMMEDIATE`，重新读取最新快照；成功修改才保存。使用 FULL 同步与 SQLite 默认回滚日志，业务变更与回执原子提交。进程中断发生在提交前则回滚，提交后保留全部结果。同一数据库的多个进程通过 SQLite 写锁串行，避免旧内存快照覆盖其他实例更新。锁等待上限 10 秒，失败通过既有错误流程返回，不声称业务成功。

持久化模式禁用公开 `/demo/reset`（409 / RESET_DISABLED），避免另一个实例仍持有旧授权时重置账本和幂等记录。内存开发模式保留原重置行为。内部后端重置方法仍供受控测试使用，不是持久化模式的用户入口。当前桌面无重置按钮。

## 配置兼容性与检查

`BankBackend`、`Service`、`create_app` 新增可选 `database_path` 参数；默认 None 保持内存测试隔离。`create_demo_app` 在设置 BANKAGENT_DB_PATH 时启用持久化，桌面自动提供默认路径。业务工具签名、金额单位、确认规则和结果结构不变。

验证覆盖重开余额及流水、重复执行与参数冲突、不同实例并发、事务保存异常、进程在提交前退出、卡片及订阅状态、未知版本拒绝、业务时钟，以及实际本地 HTTP 服务完成确认转账后关闭再启动查询。全部使用临时数据库和虚构数据，不操作用户实际账本，不调用真实模型。
