# 开发与协作流程

由用户统一推进，历史 A/B 分工和阶段排期不再作为执行规则。先读根目录 AGENTS.md，产品目标见实施方案 PR #48，实际能力以代码及验证为准。

## 开工与实施

1. 检查分支、未提交修改和相关 PR，保留用户已有改动。
2. 选择独立任务分支，明确本次效果及范围；普通实现选择自行处理，不为历史目录所有权重复请求授权。
3. 使用 [目录迁移说明](目录迁移说明.md) 中的新路径；Python 代码统一从 bankagent 包导入。
4. 目录整理不增加新业务，不改变资金、授权、请求及错误语义。新增功能另起任务。
5. 公共契约变更使用 contract/ 分支，说明原因、调用方和测试影响，由用户确认。

## 检查与交付

- 从仓库根目录运行 scripts/check.ps1；涉及启动和接口再运行 scripts/smoke_api.py。
- 记录实际代码版本和检查结果。模型替身不等于真实供应商验收，HTTP 与内存 DOM 不等于浏览器布局验收。
- 运行方式、已实现能力和限制更新 README；PPT 仅描述真实实现或明确标为目标。
- 一个任务一个 PR，提交不混入其他修改。目录迁移允许 diff 超过 400 行，需说明搬迁与行为变化的边界。
- 不直接推 main，不自动合并；合并需用户确认且检查审查头 SHA。

## 演示与结果边界

业务结果来自真实模拟后端。写操作先确认，取消不扣款；重复请求遵守幂等。页面展示后端状态，不模拟虚假的执行进度。模型错误明确显示，不静默切回关键词模式并声称模型成功。

交付目标为本地桌面应用；现有 HTTP 工作台仍作为开发入口，目录迁移不等于完成桌面打包、数据持久化或理财推荐。
