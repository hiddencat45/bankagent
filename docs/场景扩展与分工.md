# 场景扩展与分工

> 当前执行版；给双方 agent 的实现边界。下述模块化尚未实施，不能把目标接口当成现有代码调用。
> 先读 `AGENTS.md`。安全规则沿用根目录；本文件补充当前结构、接口和场景验收。

## 1. 本轮目标与目录

新增场景通常只需增加场景模块、必要后端实现和测试，无需修改公共调度器。公共机制缺失时先补机制，不为维护“一文件”口号把特殊逻辑藏进场景。

```text
preparaion/
  bank_types.py                # 共管：公共类型、枚举和常量；A 首次落地，双方确认
  bank_agent_graph.py          # A：State、公共节点、路由与图组装
  bank_backend.py              # B：模拟服务端数据与业务操作
  scenarios/
    __init__.py                # A：注册/发现与声明校验
    transfer.py               # A：转账及余额查询
    card.py                   # A：卡片
    bills.py                  # B：账单
    subscription.py           # B：订阅与代扣
    wealth.py                 # B：理财
    cross.py                  # A 主写：固定跨场景演示，另见第 7 节
  data/                       # B：最小样例、生成与一致性校验
  test_bank_agent_graph.py     # 保留原回归测试
  tests/                      # 各自：新测试、测试替身、集成测试
api/                          # A：请求校验、会话、恢复与事件
frontend/                     # B：最小演示页面
```

文中场景、后端、数据、测试路径均相对 `preparaion/`；API 和前端相对仓库根目录。PPT 脚本和素材保留原位置，共管。暂不另建 `src/` 或 `deck/`。

公共类型统一从 `bank_types.py` 导入。它仅依赖 Python 标准库，不导入图、后端、scenarios、API 或 LangGraph；只放声明和常量，不放业务执行、存储或初始化逻辑。A 在首个契约落地 PR 创建，后续接口变化双方确认，不在图和后端各复制一份。

上述是默认分工，不是固定边界。任一方积压时都可转交完整任务（含实现与测试）；先交接具体函数和测试，不让两人同时改同一段实现。后端变大后再按业务拆文件，不在首个任务强制引入多层抽象。

## 2. 开始扩展前的最小公共改造

1. 先提取现有转账与余额逻辑，保留行为；随后单独实现公共调度。原测试保留，新增行为另补测试。
2. A/B 确认下面的接口后再实现；这是建议落地的最小契约，不代表双方已确认。只冻结本阶段用到的操作。
3. 当前单操作图优先复用，不强制 `build_graph()` 永远不变。确需增加阶段时，由 A 修改并同步流程图；不能声称图和 PPT 永远无需更新。
4. 原教学转账的 float 和恢复令牌仅作为迁移基线保留，不复制到新场景；接入新的可写后端/API 前，单独完成金额和服务端授权改造。

## 3. 数据与场景接口

### 3.1 公共数据边界（由 A 落到 State，双方确认）

| 字段组 | 内容与写入方 |
|---|---|
| 可信上下文 | user_id、account_id、request_id 由服务端注入；公开请求只能提供允许的输入，不得任意合并 State |
| 候选理解 | scenario、intent、candidate_params，由规则或模型提取；不含可信 ID、授权、余额、结果 |
| 已校验操作 | operation、params，由 Python 校验并解析实体后生成；目标 ID 来自受控后端查询 |
| 安全与结果 | risk_level、operation_hash、challenge_id、authorized、result、status，由公共安全层和后端生成 |

这些是通用承载字段，避免每加一个场景都新增顶层 State 字段。允许的候选槽位由场景声明；resolve 的返回只进入 params，不允许任意覆盖整个 State。

- 新后端金额统一用整数分（例如 `amount_minor`），币种显式为 `CNY`；展示时格式化为元。其他金额表示须先约定转换边界，不能混用元/分或经过 float。
- 时间范围由 Python 规范化为明确起止日期，统一使用 Asia/Singapore，开始包含、结束不包含；测试使用固定日期。缺省值在校验阶段补齐，不能等到执行才悄悄修改参数。
- 新请求清空上一请求的候选、解析结果、计划、授权和回复。恢复中断则继续同一请求，不能当新请求重置。
- 缺槽位先明确提示；重述完整请求仅是第一阶段的过渡方案。多轮补全由 A 在公共层实现：只合并同一用户、同一待澄清任务的候选槽位，再重新解析、校验和生成计划；新话题不得复用旧授权。覆盖“只补金额”“改收款人”“切换话题”的测试。

### 3.2 场景模块

必需定义 `SCENARIO`、`INTENTS`、`execute(operation, params, context)` 和 `render(result)`。

```python
SCENARIO = "bills"
INTENTS = {
    "BILLS_QUERY": {
        "keywords": ["账单", "消费明细"],
        "slots": {"period": r"(本月|上月)"},
        "required": [],
        "operation": "QUERY_BILLS",
        "effect": "READ",         # READ / WRITE
        "risk": "GREEN",          # 静态最低风险
    }
}
```

- `execute` 仅分发到后端并返回统一结果，不在场景里修改账户、卡片或协议状态。context 由服务端构造，包含可信身份及写操作所需授权引用和幂等标识，具体类型在首个写操作 PR 中双方确认。
- `render` 只读结果，不调用工具、不修改状态；失败或处理中不能显示成功。
- 可选 `CLARIFY_LABELS`：缺失槽位的中文名。
- 可选 `resolve(candidate_params, context) -> dict`：解析实体为 params；未知或歧义实体明确进入澄清，不能任选一条。访问范围限当前用户。
- 可选 `validate(operation, params) -> bool`：附加业务校验。公共层始终检查必填项、类型及操作归属；省略钩子不等于跳过校验。
- 可选 `risk(operation, params, context) -> str`：根据可信业务状态提高风险或拒绝，不得低于声明的最低等级。非法/缺失风险属于配置错误并阻止执行。

首个实现 PR 应将参数/上下文/结果的字段落为明确的类型声明和测试样例；不要仅以 `dict` 签名作为“接口已冻结”的证据。后端函数签名、类型及失败语义双方确认后使用。

### 3.3 后端统一结果

每个操作返回：`operation`、`status`、`data`、`error_code`。状态采用 `COMPLETED`、`REJECTED`、`FAILED`、`PENDING`；成功时 error_code 为 None，其他状态需可解释原因。data 的业务字段在该操作签名旁写明并提供测试样例。

例如账单查询的 data 至少约定期间、总额（分）、分类汇总和证据交易 ID；空账单返回零额和空集合，render 不得假定总有“最大类别”。取消申请已提交但未完成时返回 PENDING。

调度器根据后端结果设置顶层 status；不能因为函数正常返回就一律标记 COMPLETED。预期业务拒绝用结构化结果；意外异常由公共边界转为失败并记录脱敏诊断，不吞掉后伪造数据。

## 4. 注册与意图选择

- 可以自动发现模块，但启用前须验证 SCENARIO、意图、操作映射、参数声明及风险合法性。不同场景不得抢占同一操作名；同场景多个意图可映射同一操作，但安全声明必须一致。
- 未实现后端不得作为可用能力暴露；测试替身仅用于测试，NotImplementedError 不能被转成成功。
- 白名单来自通过校验且已启用的声明。公共层还要验证 operation 属于当前场景，不能凭候选参数指定任意函数。
- 关键词是离线 Demo 的识别策略，不要求各场景自然语言词汇绝对互斥。收集全部命中候选，不按文件名顺序直接取第一个。
- 真实模型是另一种候选理解入口，与规则模式共用声明、实体解析、校验和安全层。keywords 不限制真实模型可理解的同义表达；模型产出的未知意图、额外可信字段或非法参数必须被拒绝或澄清，不能直接透传给后端。
- 同一操作的候选可以合并；不同操作同时命中时默认澄清。若需要更具体短语优先，显式约定规则并测试，不能按关键词列表长度猜测。
- 未识别、否定表达或多意图请求不得直接进入写操作；不支持的复合指令明确提示拆分，只有第 7 节约定的固定流程可联动。

## 5. 公共安全层与后端各自负责什么

公共安全层由 A 负责：

- READ 才能走 GREEN；WRITE 至少 YELLOW，挂失等项目约定的高风险操作为 RED。风险可以升高到 DENY，不允许场景钩子降级。
- 操作哈希至少绑定用户、账户、操作名、目标 ID、全部影响执行的规范化参数和请求标识。确认展示与实际执行使用同一份参数，参数变化必须重新确认。
- 中断前只准备可重复计算的数据；含 interrupt 的节点不得在中断前发送短信、扣款或生成不可重复流水。
- 恢复时验证当前用户、请求及挑战归属，并查询服务端授权记录；不采信 resume 中的 authorized、认证令牌或模型判断。演示可使用服务端内存授权表，但明确是模拟认证。

后端由 B 负责：

- 读写均检查账户/实体归属；写入前重查授权是否绑定本操作、是否有效，以及余额、卡片/协议状态等业务前置条件。
- 同一幂等键与同一参数重复调用返回原结果，不能重复写入；同键不同参数拒绝。原子地保存业务变更和幂等结果；内存 Demo 可加锁实现，并明确进程重启不保留。
- 后端状态是结果依据；模型和前端不得自行写余额、授权或执行结果。

上述逻辑集中实现，场景只声明业务差异。凭证、密码和 OTP 不进入 State、Prompt、Checkpoint、普通日志或测试数据；只传不含凭证的服务端引用。真实认证、持久化和完整审计不在本轮默认范围，若未实现必须在交付说明标注。

## 6. 每个场景的最小验收

- 正常输入能选对操作；未知/歧义/否定请求不会误执行。
- 缺字段、非法参数、未知实体能澄清或拒绝；跨用户访问被拒绝。
- 风险与声明一致，动态策略只能升高；写操作缺少有效授权无法执行。
- 后端成功、拒绝、失败的结构符合契约，render 不编造事实；只读场景验证空数据，写场景验证重复提交和参数被替换。
- 至少一条使用实际模拟后端的图集成测试；只有 stub 单测不能算场景完成。
- 涉及页面的场景应验证实际卡片、按钮和最终后端状态；新增模型理解需覆盖同义表达、非法输出及超时。固定数据中的异常标签仅供测试校验，不返回给模型当作检测结果。
- `scripts/check.ps1` 通过，确认新测试实际被收集。新增测试放 `preparaion/tests/`，当前脚本在 preparaion 下执行 pytest；若以后迁出此目录，必须同步门禁发现范围。

不放宽旧断言来掩盖回归。调整 import 等测试迁移可随机械拆分完成；有意改变行为时单独说明原因和预期，增加覆盖新行为的测试，不偷偷改旧期望。

## 7. 固定跨场景演示

本轮只做固定串联，不默认实现通用 DAG、长任务表、自动补偿或任意工作流。跨场景由 A 主写，B 提供后端支持；所依赖的场景实际可用后再接。

推荐流程：查账单 → 展示疑似异常和证据 → 用户选择协议 → 生成取消计划 → 按公共安全规则确认/认证 → 后端执行 → 展示实际状态。

查询发现异常不等于授权取消。每个写步骤独立校验、授权和幂等；前一步失败就停止并展示已完成部分，不把整个流程说成成功。cross 不得绕过公共安全层直接调用写后端。若现有图无法表达，由 A 明确增加编排入口并测试，不把多个副作用藏进一次 execute。
