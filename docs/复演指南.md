# 当前正式入口复演（2026-11-01）

本节适用于 `feat/submission-interface-polish`。后面的10月27日流程为历史记录，不能用于当前注册客户。已有用户继续原来的 Youdu.exe，不改账本、不切换隔离测试入口。新电脑按 README 克隆当前分支并 setup 后双击 Youdu.exe。

## 双客户卡间转账

1. 登录页选择注册，创建两个不同用户名、各自密码的本地客户A、B。显示姓名可以重名，以下为便于观察分别使用张伟/王芳。已有账号可直接登录，不重复注册。
2. 分别登录，按首次引导开账户，再从“账户与卡”申请、激活借记卡。注册、开户和激活后余额均为0。B在卡详情复制自己的本地卡号，退出登录；不要发送密码给A。
3. 登录A，从“账户与卡→模拟入金”选择本人已激活卡，显式确认10000元虚拟资金。资金不是真实存款，不是注册赠款。使用已有资金演示时记录实际起始余额，不为凑数字重置。
4. 转账页选择A付款卡，粘贴B卡号，输入1000。核对服务端返回收款姓名、卡尾号、金额及安全等级。首次转账引导重新验证登录密码并设置独立6位交易密码，再完成确认认证。A余额9000，B余额1000。
5. 再准备5000元转账，确认卡应说明客户全部卡当日预计累计6000元、超过1000元，因此追加手机验证器动态码。右上“更多→绑定手机验证器”，用身份验证器添加二维码（不是微信扫码），输入动态码完成绑定，再回原单确认。密码/动态码只填专用窗口，不发送给AI。成功后A余额4000，B余额6000。
6. 打开“交易记录”，选择当前月份。应有入金10000、转出1000、转出5000，汇总分别入账10000、转出6000、消费0。点击5000元行，右侧查看详情；展开流水编号核对关联。按王芳搜索、切换月份、重置、查看空结果。
7. 准备30元后取消，A仍为4000；不应有30元已完成流水。退出登录后登录B，查两笔转入总6000。关闭并重开同一个EXE，分别登录核对双方账务；不重新付款来确认旧结果。

当前模拟业务日为2026-10-18，因此“本月”与操作系统日期可能不同，应以界面服务端日期为准。实际日期/流水号由后端提供，不用截图值代替。

## AI与安全分级演示

模型配置见README。打开悬浮球，依次尝试：

- “我现在能用的钱还有多少？” → 返回本人实际余额。
- “看看这月给王芳的转账，一共花了多少？” → 汇总实际两笔转账。
- “给卡号【粘贴B卡号】转40元，先让我核对再付” → 展示真实确认，尚未扣款。
- “先取消这笔，不要扣钱” → 取消待办，余额不变。

不必为了展示认证反复绑定手机。演示重点是查询低风险、普通转账确认＋密码、累计超过阈值追加验证，以及冻结/余额不足等禁止执行边界。已绑定验证器的客户直接使用即可。没有手机时可以展示规则与待认证状态，不能点击模拟成功冒充多因素认证。

本轮自动化实际HTTP和真实模型记录见[提交前核对](提交前核对-20261101.md)。此手册是可复现操作，不代表上述每一步均由真人点按验收；本轮未进行真实手机扫码和全新电脑安装验收。重开持久化及安全失败已有自动化覆盖，见对应测试与历史分层证据。

## 演示前最后检查

- 原EXE能正常登录、卡片与账单属于本人；不公开密码、二维码或完整真实金融身份。
- 联网模型可用；若失败明确说明，普通表单可继续，不将离线规则宣称为真实模型。
- 新用户无初始资金；需要资金时显式模拟入金。
- 结果未知时核对原操作，不新建付款；演示完成保留流水便于复查。
- PPT仍需对齐当前版本，正式比赛材料和提交期限另行核对。

# 陌生人可执行的完整演示

目标：亲自完成开户、发卡、消费、双边转账、核对另一客户入账、重开查询；再检验模型的追问、修改/取消与批量。仅虚构数据。此分支尚未合入main，不能直接克隆main并期待所有能力存在。

## 1. 环境与账本

Windows、Python 3.10、Git；开发门禁另需Node。网络用于安装依赖与真实模型。PowerShell运行README的克隆与setup-desktop命令。若脚本执行策略阻止，应按本机管理要求处理；本指南不修改系统策略。未在全新机器完成安装验收。

首次演示建议显式指定新目录的账本，保持当前PowerShell不关；**已有文件则直接重用，不删除重置**：

```powershell
$env:BANKAGENT_DB_PATH = Join-Path $env:LOCALAPPDATA 'BankAgentDemo\walkthrough.sqlite3'
.\start-desktop.cmd
```

底部核对账本路径。关闭窗口后，从同一PowerShell运行相同命令再开。若另开终端，重新设置同一路径；默认双击会使用配置的账本而非上述进程变量。目录不可写应修复原路径或主动指定另一份演示账本，应用不会悄悄换库或清空。

真实模型需供应商兼容的聊天工具调用接口。设置`BANKAGENT_MODEL_BASE_URL`和`BANKAGENT_MODEL_NAME`为供应商实际值，密钥可通过Windows用户环境变量配置，不贴进聊天或文档。也可在当前终端安全输入：

```powershell
$demoSecret = Read-Host '模型API密钥' -AsSecureString
$env:BANKAGENT_MODEL_API_KEY = [System.Net.NetworkCredential]::new('', $demoSecret).Password
$demoSecret = $null
# 按供应商资料设置实际 BASE_URL / NAME 后启动；不要照抄占位地址。
.\start-desktop.cmd
```

窗口应显示“真实模型”；缺失配置时明确“离线规则”。配置不完整可能启动失败，不用假模型覆盖。模型不可用时普通表单仍可演示；自然表达专项标为未验收。

## 2. 完整业务链（默认界面，普通表单）

2026-10-28 更新（任务分支未合并）：正式入口现在默认登录现有张伟账户，重开/重新连接也回到张伟。下方历史付款方流程开始前，先在左下客户菜单选择“默认演示客户”。新账本的张伟目前没有预置收款联系人；本轮只调整默认登录，不补联系人或复制原客户账户/卡片。账户和流水展示以所选客户实际数据为准。

新演示账本默认客户余额5000元，张伟400元；若是重用账本，以实际起始余额和差额核对，勿为凑数重置。当前业务日期按演示基准2026-10-18，“本月”不是操作系统当前月份。

1. 点“开户”，名称填`旅程账户`，核对后确认。该账户实际增加1000元演示入账。在账户下拉选择它并切换，核对当前账户身份。
2. 点“办理借记卡”，名称`旅程卡`，确认。先尝试刷卡12元，商户`演示书店`、分类购物，确认后应提示未激活且余额不变。
3. 点“激活”，填`旅程卡`并确认。再刷卡12元，确认后余额988元，流水新增12元消费。
4. 点“转账”，收款人`张伟`，金额`37.50`。核对确认后当前账户950.50元。点“本月流水”，消费统计仍12元，转账单独列出且有双方关联编号。
5. 演示客户下拉选张伟并切换，核对余额437.50元及转入37.50元。切回默认客户，再选旅程账户，余额仍950.50元。客户端不传任意user_id。
6. 关闭窗口并按原路径重开；启动身份为张伟，先切回原默认客户，再切到旅程账户，读本月流水，余额950.50元、消费12元与转账37.50元仍在。旧聊天/确认不会恢复；不要重新发起同一笔付款代替查结果。

这条精确金额链已由`scripts/replay_delivery_demo.py`通过实际桌面HTTP客户端和子服务复演：1000→988→950.50元，张伟400→437.50元，退出并重新启动子服务后双方余额及可见账单文本相同。记录见[evidence/delivery-http-20261027.json](evidence/delivery-http-20261027.json)。这是自动化真实HTTP证据，仍待陌生人亲自按窗口复演，不冒称用户验收。

另外验证创建客户：点“创建演示客户”，虚构姓名`演示小禾`，首账户`日用账户`，确认后从客户列表切换，应该为1000元；申请/激活自己的卡。新客户没有联系人维护页，因此这条路径暂时不能完整演示新客户转给任意联系人。不要通过任意user_id绕过。

## 3. 模型表达与确认

切回默认客户默认账户再测试。以下是本轮实际采用的表达，产品没有新增对应固定字符串分支；可以换人名、金额与措辞，记录新结果。

- “这个月的钱主要用在哪些地方？”→“吃饭这一类单独给我看看”→“其中一笔超过一百块的留下”→“金额条件撤掉，换成出行那一类”。核对时间、类别、金额筛选及实际流水。
- “向张伟汇四十六元”→待确认时“数额换成二十九块，收款人不变”→“先别付，我要知道现在余额”→“这一笔彻底作罢”。均不点批准，余额不应变化，旧确认失效。
- “看看我还有多少钱，如果够，就给张伟汇三十七块五毛，最后列出这笔流水。”应先查余额、展示确认，批准后双边入账并再查流水。
- “张伟收十八块，李娜收二十三块五，请合成一批让我核对，完成后查回执。”只能一次确认完整列表与41.50元；一项失败整批不扣款。点“批量回执”，重开后仍能查询已完成批次。
- “把我的借记卡列一下”→“把第一张临时冻结”。务必核对实际卡名再决定批准；同名或无列表时应澄清，不能猜。
- “我能拿出两千元，三个月后要用，不愿承受本金损失，有什么理财适合我？”当前会说明不支持。**这是未完成项，不是推荐演示成功。**

遇到模型错误、轮次预算或网络失败，记下输入、当前身份、是否已确认和可见结果；不删失败记录。付款结果未知时使用“重试原决定/核对结果”，不另外提交付款。高风险可按文末本机模拟认证步骤继续；真实银行认证尚未接入。
