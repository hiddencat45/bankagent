## 一、现状诊断

项目能跑、测试也厚，但目录结构还停留在「两个人快速迭代」的阶段。按严重程度排：

| # | 问题 | 证据 | 影响 |
|---|---|---|---|
| 1 | **715 行死代码** | `preparaion/bank_agent_graph.py`（510 行）被注释标记「旧教学文件暂不改」；`preparaion/test_bank_agent_graph.py`（205 行）第一步就是 `skipTest("has not been implemented yet")`，**永远跳过** | 新同事看到两个 `build_graph`，不知道哪个在跑；`pytest` 里混着一条永不执行的用例 |
| 2 | **包名拼错了** | `preparaion`（应为 preparation） | 一旦 import 路径写进代码，就是永久性拼写债；改名成本随时间线性上升 |
| 3 | **靠 sys.path 工作，不是包** | `pytest.ini` 写 `pythonpath = . preparaion`；启动用 `uvicorn --app-dir preparaion` | 不能 `pip install -e .`，IDE 跳转与类型检查都靠猜 |

| 5 | **素材混在代码包里** | `preparaion/` 下有 `assets/`（架构图）、`deck-preview/`、`frontend-mockup-render/`、`style-preview/`（幻灯片截图） | 装包时会带上 PPT 截图 |
| 6 | **测试混在产品目录** | `preparaion/test_bank_agent_graph.py` 与 `preparaion/tests/` 并存，两套规则 | 不知道新测试该放哪 |
| 7 | **单文件承载整张图** | `agent_graph.py` 687 行，`build_graph` 里嵌 18 个闭包节点 | 改一个节点要通读全文；这也是「防御性代码越堆越多」的温床 |
| 8 | **前端目录语义模糊** | `frontend/` 同时放 dev server（`dev_app.py`）与静态资源 | 前后端边界看着像一层 |

顺带：仓库根目录还躺着一批 `pip-install-*` / `pip-build-tracker-*` 临时目录（未跟踪，但污染 `ls`）。

## 二、参考：成熟 agent 项目的共同结构

看 LangGraph 官方模板（`langgraph new` 生成）、OpenAI Agents SDK、CrewAI 这几个，结构上高度一致：

1. **`src/` layout** —— 包在 `src/<pkg>/` 下，杜绝「从当前目录import」的隐式路径
2. **单一 `pyproject.toml`** —— 依赖、测试、lint 配置都在这一个文件里
3. **图定义与节点分离** —— `graph.py` 只负责装配，节点各自成文件或成组
4. **`state.py` 独立** —— 状态类型单独一处，不散在图里
5. **能力单元独立目录** —— `tools/` 或 `nodes/`，按职责分，不按「谁写的」分
6. **`tests/` 在产品包外** —— 与源码平级，不嵌进包里

我们的项目在 1、3、4、5、6 上都能对上，缺的是 2，以及把 7 落实。

## 四、分三步走

### 第一步：无损清理（低风险，约 1 天）

只做**不改变任何 import 路径**的事，理论上零冲突：

- 删除 `bank_agent_graph.py` 与 `test_bank_agent_graph.py`（−715 行）
- 素材目录归位：`preparaion/assets` → `docs/assets`，其余三个截图目录移出仓库或进 `.gitignore`
- `preparaion/test_bank_agent_graph.py` 之外的散落测试归入 `tests/`
- 新建 `pyproject.toml`，`requirements.txt` 改为「直接依赖 6 条」+ 可选 `requirements.lock.txt`
- 清理根目录 `pip-install-*` 临时目录并加进 `.gitignore`

风险：**低**（只需保证 700+ 测试仍全绿）。

### 第二步：改名与分层（中高风险，约 2 天）

- `preparaion/` → `src/bankagent/`（顺带修正拼写）
- 内部按 `graph/ domain/ agent/ llm/ scenarios/ data/` 分层
- `frontend/` → `web/`
- 移除 `pytest.ini` 的 `pythonpath` hack，改用 `pip install -e .`
- 改所有 import、启动命令、`scripts/*.ps1`、CI

**风险点**：这一步会让**所有在途分支冲突**。必须满足两个条件才动手：
1. Zason42 手上没有未合并的分支
2. 一次性做完，不分多次（半改名状态比不改更糟）

### 第三步：拆分大图（可选，中风险，约 1 天）

## 五、明确不做

- **不引入 DI 框架**（FastAPI 自带依赖注入够用）
- **不拆成多服务**（演示场景，单体更稳）
- **不上 monorepo**（一个产品，不需要）
- **不为了「像大厂」加抽象层**（每加一层都要有人维护）
