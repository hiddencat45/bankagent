## 问卷与筛选规则

问卷无预选答案，十项必填：总预算、扣除必要支出和备用金后的闲钱、最早用钱前的天数、用途、到账要求、亏损态度、收入稳定性、还款压力／借款来源、非保本理财经验、偏好。保存前展示全部答案并确认；按客户保存，365天后要求更新。流水不自动推断闲钱或风险承受能力。

硬性排除：用于必要支出、存在还款压力或借款理财、预算超过闲钱、不能承受本金亏损、要求当天或固定日期到账、预算低于起投、期限不足以覆盖模拟确认＋持有＋到账。无经验、收入不稳定或只接受低风险时，模拟范围最多R1；接受波动、有经验且收入稳定时才可纳入R2。不是银行C1—C5测评，不生成正式评级。

输出每款产品的通过／排除理由。偏好仅作为已确认需求展示，不编造收益排名或虚假精确评分。申购执行时重新检查问卷、产品条件、当前卡状态、可用余额，以及本人所有账户的持仓＋申购冻结＋待到账资金是否超过预算。预算不是单笔额度。

示例：

| 用户明确回答 | 筛选结果 | 行为 |
|---|---|---|
| 预算2000、闲钱6000、90天、闲置资金、可等待、有经验、收入稳定、接受波动、无还款压力 | 三款均通过模拟初筛 | 可比较差异；选定后申购仍须强认证 |
| 同上，但没有非保本理财经验 | 仅R1的华夏进入模拟候选 | 不因余额充足把用户升级为R2 |
| 同上，但这笔钱用于必要支出、不能亏损或要求当天到账 | 无候选 | 明确拒绝推荐，不强行凑一款 |

## 交易、状态与账务

```mermaid
flowchart LR
  A[问卷确认] --> B[确定性筛选]
  B --> C[准备申购]
  C --> D[交易密码与TOTP]
  D --> E[提交并冻结资金]
  E --> F[受理]
  F --> G[确认份额]
  G --> H[持有期届满]
  H --> I[赎回确认并锁定份额]
  I --> J[受理并扣减份额]
  J --> K[资金待到账]
  K --> L[到账并增加现金]
```

| 状态 | 账务意义 | 可进行的演示动作 |
|---|---|---|
| `SUBMITTED` | 申请已提交；申购冻结现金／赎回锁份额 | 受理、撤单、拒单、模拟超时 |
| `UNCERTAIN` | 受理回执不确定，保留锁定 | 下一步查询原订单，不自动释放或重下 |
| `ACCEPTED` | 已受理，尚未成交 | 全部确认、半数成交、撤单、拒单 |
| `WAITING_CASH` | 赎回份额已扣，现金尚不可用 | 到账或演示延期 |
| `SETTLED` | 申购份额已确认，或赎回款已到账 | 终态，不再次入账 |
| `CANCELLED` / `REJECTED` | 未成交部分已释放 | 终态 |

半数成交向下取到0.01份，剩余申请结束并释放。订单另存申请量与成交量，界面显示“部分成交”，不能把申请量当成交量。赎回按申购批次分配已解锁份额，锁定份额不可重复赎回；“全部”仅填入所选产品当前可赎回份额。拒单和撤单均保留事件记录。

现金变动写入原账单：`WEALTH_RESERVE`冻结、`WEALTH_RELEASE`释放、`WEALTH_CREDIT`到账，并关联订单号。可用现金＋冻结＋持仓＋待到账在本版固定净值无费用条件下守恒；不同科目不能相互重复计算。SQLite事务一次提交余额、订单、持仓、事件及幂等结果，异常整体回滚。

## 架构及接口变化

- `banking/wealth.py`负责产品、问卷、确定性筛选、订单状态机和资金变更；复用现有`_lifecycle_write`与SQLite事务。
- `agent/scenarios/wealth.py`注册7个动作并校验参数。`QUERY_WEALTH`、`RECOMMEND_WEALTH`为只读，其余为确认写操作。`SUBSCRIBE_WEALTH`必须是RED授权，后端拒绝降为YELLOW的记录。
- 新增可信会话只读接口`GET /bank/wealth`，拒绝外部传入账户；`POST /bank/form`新增上述理财动作。模型和普通页面走相同图及授权路径。订单变更绑定订单号＋版本；日期推进绑定原日期。
- `desktop/wealth.py`提供产品筛选、问卷、持仓、订单与演示四个页签；`AuthenticatedWindow`申购调用既有交易密码与TOTP弹窗。开发工作台仅兼容新增账单类型，未制作第二套理财界面。
- 理财最终事实使用确定性服务端展示；模型负责理解、补问和选择工具。真实模型首轮曾把分误读成元，修正后由回执直接展示金额；这项保护不代表其他场景绝无幻觉。

没有新增依赖或独立资金数据库。聊天／未确认草稿仍不跨重启；已经提交的理财订单、份额、事件和账务持久化，重启后查询原订单再继续。

## 安全自评与已知风险

身份来自登录会话，账户来自服务端选择；模型不能指定授权用户或宣布认证成功。确认绑定身份、请求、动作和具体参数；认证不出现在聊天、模型Prompt和业务回执中。业务层再次检查卡、余额、问卷、预算、可赎回量与订单版本。拒绝不改变账务；重复确认重放原结果。

本地正式登录版使用独立交易密码和TOTP。错误5次锁15分钟，TOTP校验带防重放和操作绑定；凭据由既有认证模块保护。验证器绑定是本地演示账户机制，不是银行实名或可信设备认证。普通开发模式的本机模拟码不应展示为赛事生产认证方案。

当前缺口：未接真实银行／产品行情；非正式适当性测评；无真实费率计提、涨跌、分红或节假日清算；不模拟极端市场或所有渠道拒绝原因；没有独立防篡改审计平台；本机管理员可改数据库；无验证器丢失后的安全恢复；不提供通用任务DAG、OS级代码执行沙箱或跨系统最终一致性。锁定覆盖认证失败，不声称已覆盖所有业务异常。现有卡冻结功能不能冒称带完整强认证的挂失／解挂业务。
