# 有度 · 银行 AI 智能体

PySide6 本地银行模拟应用。模型理解请求并提出工具调用；服务端决定身份、授权、资金规则与结果。普通表单与 AI 共用准备、确认、认证、执行及 SQLite 账本。没有接入真实银行或真实资金。

## 当前版本与入口（2026-11-01）

当前交付分支为 `feat/brand-header-refinement`，承接 #76–#90 的未合并功能；**main 不包含这些最新能力**。此前 #56、#61–#74 于10月28日合并，仅代表当时版本。本轮不合并 PR、不推 main。

本机继续双击项目根目录 **Youdu.exe**。关闭旧窗口再打开即可加载新界面；原账号、密码和账本绑定不变，不需要重新注册或更换测试入口。

Youdu.exe 是内嵌机器人图标的启动器，调用项目 `.venv`，不是独立安装包。私有 `Youdu.ledger-path` 指定原账本绝对路径；路径无效时拒绝启动，不自动换库。此文件、数据库、凭据不得提交 Git。新安装没有此文件时按正常默认路径创建本地账本。

品牌与页头更新：绿色交织标志、精简侧栏底部、右上头像菜单和固定账单卡片选择已接入现有数据；完整账本路径见头像菜单“诊断信息”。实际窗口见[桌面应用](docs/桌面应用.md#品牌与固定页头修正2026-11-01待审)。

## 当前能力

- 独立注册和登录页面：唯一用户名＋登录密码。注册仅创建客户；开户、发卡、激活均不赠款。旧无凭据客户保留但暂不开放登录认领。
- 客户可持有多账户、多卡；普通借记卡一账户一卡。显式模拟入金仅用于虚拟资金，每笔最多10000元。旧余额、流水及卡分户历史不重置。
- 普通表单完成开户、借记卡生命周期、模拟消费、按卡号转账。收款卡必须属于当前本地账本，无须预先加入通讯录；不能转往真实银行。
- 转账使用独立6位交易密码。同一客户名下所有账户/卡当日累计转出含本次**超过1000元**时，追加手机验证器 TOTP；恰好1000元只需交易密码。冻结、余额、限额、归属规则仍由服务端执行前复核。
- 单笔双边记账、批量一次确认且整批原子提交；取消不扣款，重复确认遵守幂等。金额或对象修改使旧确认失效。
- 统一 Agent 查询—准备—确认—执行—复查回路；待确认时可修改、取消或先查询。模型错误明确失败，不伪造模型成功。
- 真实交易记录：按月/自定义日期、类型、分类和对方筛选；入账、转出、消费分开汇总；选中行查看结构化详情和关联编号。页面与助手读取相同业务数据。
- 深绿侧栏与统一弹窗样式，悬浮球展开半透明助手，聊天气泡及业务确认卡。收起不清空当前对话/草稿；退出登录会清理敏感展示。

登录/交易密码连续错误5次锁15分钟，重开不清除计数。密码不进入模型。登录密码＋交易密码并非双因素；手机TOTP为额外因素，仍不代表银行实名核验或生产安全标准。安全分级说明位于右上“更多”；二维码须用身份验证器添加，微信扫码不是验证流程。

## 新电脑从源码运行

Windows、Python 3.10、Git；开发门禁另需 Node。PowerShell 在目标目录运行：

```powershell
git clone --branch feat/brand-header-refinement https://github.com/hiddencat45/bankagent.git
cd bankagent
.\scripts\setup-desktop.ps1
.\Youdu.exe
```

不要从别人的机器复制私有账本绑定文件。setup 生成启动器需要 Windows .NET Framework 4 C# 编译器；本轮未在全新电脑验收安装。旧 `.cmd` 留作开发兼容入口，已绑定账本的日常用户统一使用 EXE。

真实模型配置 `BANKAGENT_MODEL_API_KEY`；兼容接口地址和模型名通过 `BANKAGENT_MODEL_BASE_URL`、`BANKAGENT_MODEL_NAME` 配置，未设置时使用代码默认 DeepSeek 地址和模型。不要把密钥写进仓库或聊天。没有模型配置时界面明确显示离线规则；普通表单仍能办理业务，离线规则不代表自由自然语言能力。

完整双客户操作见[当前复演指南](docs/复演指南.md)，安全规则见[高风险转账认证](docs/高风险转账认证.md)，接口见[本地登录](docs/本地登录实施状态.md)与[按卡号转账](docs/按卡号转账.md)。

## 本轮实际证据与边界

[提交前核对](docs/提交前核对-20261101.md)记录本轮窗口、HTTP、模型、门禁及未完成项；[交付核对](docs/交付核对.md)保留各历史版本证据。测试数与截图只对应其记录版本，不代表泛化成功率。

- 两个新注册测试客户显式入金10000元，转出1000元和5000元，双方余额4000元/6000元；页面实际显示三笔流水。临时账本，不改日常资金。
- 真实模型实际TCP HTTP：查余额4000元、汇总给王芳转账6000元、按卡号准备40元、取消后不扣款。记录保留原始公开答复，也保留结果卡重复/口径不够聚焦的现象。
- Windows 实际窗口125%/150%缩放及紧凑窗口验证；模型专项使用离屏控件，不冒称真人手机或实际窗口模型联合验收。

尚未完成：理财推荐（按用户决定暂缓）、独立签名安装包与macOS发行、全新电脑安装验收、验证器丢失后的安全恢复、真实银行接入。聊天、任务草稿和待确认不跨重启恢复；已完成账务和幂等结果持久化，应重开查询原流水而非重复付款。模型长任务与任意措辞仍可能失败。

[PPT](presentation/有度-银行AI智能体全流程规划.pptx)仍是旧版本，不能作为当前功能清单。比赛最终PPT/视频、官方材料格式和截止日期尚需核对；本轮目标为可复演的本地演示和代码审查，不宣称已具备所有正式参赛提交材料。

## 开发与架构

`src/bankagent/agent` 为模型回路，`banking` 为账务与存储，`api` 为 HTTP/SSE 与会话，`desktop` 为 PySide6 客户端。`frontend` 仅为开发工作台。架构、开源参考与 VitaBench 评估启发见[架构与边界](docs/架构与边界.md)；未运行或通过 VitaBench 官方基准。产品范围见[实施方案](docs/bankagent-实施方案-2026-10-26.md)。

开发检查使用临时账本，清除日常账本/模型进程变量后执行：

```powershell
.\scripts\check.ps1
.\.venv\Scripts\python.exe scripts/smoke_api.py
# 显式验收脚本自动创建临时账本，输出选新目录，失败不覆盖。
.\.venv\Scripts\python.exe scripts/audit_submission.py --output .desktop-tmp/my-audit
# --visible 会打开真实窗口；--live-model 会调用真实供应商并产生费用。
```
