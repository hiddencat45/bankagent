# 有度 · 本地工作台

复用根目录 API 的真实模拟账本、服务端会话和授权。默认离线规则模式，
未连接真实银行或大模型；理财、卡片、订阅、跨场景联动尚未开放。
页面接受服务端声明的 offline/model 模式；实际模型由后端配置。多轮补全需配合后端 PR #18，
模型适配边界需配合 PR #19；只运行本前端分支不会自动获得这些后端能力。

## 启动

在仓库根目录，先按根 README 用现有 `.venv` 安装锁定依赖，然后执行：

```powershell
.\.venv\Scripts\python.exe -m uvicorn frontend.dev_app:create_app --factory --app-dir preparaion --host 127.0.0.1 --port 8021 --workers 1 --no-access-log
```

打开 <http://127.0.0.1:8021/>，点击「开始演示」。页面与 API 同源，不需要另开前端服务器。
只支持本地单进程单实例；Ctrl+C 停止服务，重启后内存数据恢复。

页面通过 `POST /demo/session` 获取短暂令牌，可信身份由服务端选择；
令牌不进入对话记录、日志或浏览器持久存储。静态入口只挂载本目录，不暴露仓库根文件。

## 通信与确认边界

- `agent-client.mjs`：标准 POST fetch/SSE，支持中文分片、CRLF、心跳与多行 data；同轮信封归属一致。
- done 只结束流，等待确认/澄清、拒绝、失败都不转换为成功；断流不自动重发 POST。
- 确认只回传当前 thread/challenge 与决定，不回传金额、身份、授权结论或改写后的执行参数。
- 重发确认必须由用户明确选择并沿用同一挑战/决定，服务端仍负责幂等与授权。
- 确认断流后，RUN_BUSY 或临时 HTTP 错误保留未决状态与重试按钮；终态或明确的卡片/会话失效才清除。
- 重置响应丢失不自动重发、不假称成功；再次收到 401 时清除失效会话和旧确认，恢复「开始演示」，由用户重新连接查询余额。
- 模拟业务日期与浏览器当天可能不同，页面不按浏览器日期误判过期；每次确认由服务端重新校验。
- 高风险独立认证未接入，页面不收集或保存 OTP。服务端默认拒绝高风险批准。
- 所有业务文本通过 textContent 展示，不将模型或后端文本当作 HTML 执行。

## 卡片接入进度

本功能分支已实现卡片查询、冻结/解冻后端，以及页面的列表、确认卡和操作回执展示，
沿用 #26 提案。卡片场景和 API 确认投影尚待接入，当前运行页面仍只开放原有业务，
不能把组件测试中的模拟事件当成可用的卡片聊天功能。

后端接口为 `query_cards(context=...)`、`freeze_card(context=..., card_id=...)`、
`unfreeze_card(context=..., card_id=...)`。写操作必须绑定服务端已批准挑战；
不改变余额或历史流水，也没有刷卡扣款路径。同请求重放返回原操作回执，
后来解冻不会因重放旧冻结请求再次被冻结；页面提示另行查询当前状态。

联调时应核对查询→选定卡片→确认/取消→冻结→解冻的后端与页面结果，
以及旧按钮、同名对象澄清、跨账户拒绝和重放。当前列表/确认采用提案字段，
同名对象选择协议尚未完成，不提供自行猜测实体的快捷按钮。

## 订阅演示（本功能分支可运行）

沿用上面的工作台启动命令。点击「本月账单」查看疑似重复扣款证据，
再点「查看已登记的订阅与代扣」或左侧「订阅与代扣」。
本期协议实际扣费共230元：演示订阅两笔共50元（月度约定25元）、
通勤月票60元、已暂停工作餐月卡的历史扣费120元。它们是账单消费的子集，
不改变原消费总额1000元或初始余额5000元。

点演示订阅的「申请暂停此代扣」只填入请求；发送后还须核对并确认。
取消不变更，确认后模拟协议变为PAUSED、计划扣费日清空，原50元证据仍在。
支持同确认重放和失败后原请求重试，重置恢复初始状态。
尚未模拟后续自动扣款，也不代表退款或商户合同取消。
当前支持明确名称；同名或“这个/它”无法确定对象时要求澄清，不猜测实体。
